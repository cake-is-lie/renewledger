# RenewLedger · 续费账本

记录订阅、域名、服务器这类定期续费的小工具。使用 C# / .NET 10 和 Razor Pages，数据保存在本机 JSON 文件中。

## 运行

需要先装 .NET 10 SDK，然后在项目目录执行：

```sh
dotnet run --project RenewLedger.csproj --urls http://localhost:5080
```

浏览器打开 http://localhost:5080 。没有账号系统，只适合在本机用，不要直接暴露到公网。

在终端按 `Ctrl+C` 停止服务。服务关闭时不能访问账本，也不会发送提醒。

## 功能

- 增删改月付或年付项目，可以按名称搜索
- 保存失败时保留表单输入，输入错误显示在对应字段附近；文件读写错误单独提示
- 编辑、删除、续费和备份操作保留搜索与筛选条件
- 按币种分别统计启用项目的预计月均固定支出，年付按 12 个月折算，不做汇率换算
- 列出启用项目中未来 7 天（含今天）内到期的项目，以及已经过期的项目
- 月付、年付保留续费锚点，可选择固定日期或月末规则，不再逐月漂移
- 停用后保留记录和备份，但不再计入预计支出、到期统计或续费操作；可筛选启用和停用项目
- 续费前核对当前金额和新旧日期；重复提交、失效确认和旧编辑页不会覆盖新数据
- JSON 导入导出，导入前需要确认，并会检查数据格式和重复 ID
- 账本为空时可以一键加载示例数据

## 续费规则与停用

固定续费日为 1–31 日。目标月份没有该日时暂取该月最后一天，后续仍使用原锚点：

| 选择 | 示例 |
|---|---|
| 月付，固定 31 日 | 2026-01-31 → 2026-02-28 → 2026-03-31 |
| 月付，固定 30 日 | 2026-04-30 → 2026-05-30 |
| 月付，月末规则 | 2026-04-30 → 2026-05-31 |
| 年付，2 月固定 29 日 | 2028-02-29 → 2029-02-28，2032 年恢复 2 月 29 日 |

年付保留到期月份；月末规则表示该月份最后一天。勾选月末规则后优先使用它。编辑时会显示现有锚点，**只改价格不会重置锚点**。修改到期日或周期时请同时核对规则；不一致时页面会保留输入并提示错误。固定续费日留空表示按输入的到期日重新建立锚点。

点击“确认续费”只打开预览，不改账本。核对项目、当前周期金额和新日期，勾选确认后，才从**原计划到期日推进一个周期**，不是从付款日或今天重算。逾期补缴一次后可能仍然过期；若已补缴多个周期，可逐次确认，或在编辑页明确修正日期。

续费确认目前只更新计划日期，**不记录实际付款日期、实际金额或付款历史**。套餐涨价时先编辑价格，再重新打开确认页。打开确认页后若记录已续费、编辑、停用、删除或重新导入，旧确认会被拒绝；同一确认并发提交也只成功一次。旧编辑页同样不能覆盖已经更新的记录，失败时保留输入，需要重新打开编辑页核对后保存。

取消订阅时，在编辑页取消勾选“启用此项目”。停用项目仍可搜索、编辑、导出和重新启用；重新启用不自动推进日期。停用不是删除或完整归档，目前没有撤销续费。

本阶段只实现 v0.2 核心功能。分类、备注、季度/自定义周期、一次性到期、完整归档及撤销留待后续；付款历史和 SQLite 尚未引入。

## 数据存储

默认数据路径是应用内容目录下的 `data/ledger.json`。从项目目录运行时，就是项目里的 `data/ledger.json`。金额用 `decimal`，日期用 `DateOnly`。

可以用环境变量 `Ledger__Path` 指定其他位置。建议使用绝对路径，把长期数据放在程序目录以外。例如，在 PowerShell 中：

```powershell
$env:Ledger__Path = Join-Path $HOME 'RenewLedger/ledger.json'
dotnet run --project RenewLedger.csproj --urls http://localhost:5080
```

Linux shell 中可这样运行：

```sh
Ledger__Path="$HOME/.local/share/renewledger/ledger.json" \
  dotnet run --project RenewLedger.csproj --urls http://localhost:5080
```

**更换路径不会自动搬迁旧账本。** 请先导出旧账本，再在新位置导入；之后启动时使用相同的路径配置。

当前最多支持 1000 条记录。只允许一个应用进程管理同一个账本文件，不支持多个实例同时写入。不要在服务运行时手工编辑账本。

## 备份与恢复

### 正常账本

- 点击“导出”，将 JSON 备份保存在程序目录以外。
- 导入只接受 2 MB 以内、格式版本为 `1` 或 `2` 的备份，会检查必需字段、数据范围、续费规则和重复 ID。导出使用版本 `2`。
- **导入会替换整个账本，不会合并。** 先导出当前数据，再选择备份并勾选替换确认。
- 无效备份不会修改现有账本；成功导入后检查项目名称、币种、金额和到期日。

### 账本损坏

损坏账本会显示错误，应用不会将它清空，也不允许用页面导入直接覆盖它。导出损坏账本同样会失败。恢复步骤：

1. 按 `Ctrl+C` 停止服务，确认没有其他实例正在使用该文件。
2. 确认实际数据路径：设置了 `Ledger__Path` 时使用该路径，否则使用默认路径。
3. 将损坏文件重命名为其他文件名，例如 `ledger.corrupted-20261006.json`；保留原文件，不要删除，也不要覆盖已有的同名文件。
4. 使用原来的路径配置重新启动服务。原路径现在没有账本，页面会显示空账本。
5. 通过页面导入一份已知有效的 JSON 备份。若没有有效备份，先保留损坏文件，不能保证恢复全部记录。
6. 检查恢复结果，再导出一份新的备份。

读写失败也可能由权限、磁盘空间或文件被其他程序占用导致。先排查这些问题，不要把权限错误当成账本损坏而直接替换数据。

### 更换程序版本

升级前先用旧程序导出备份并停止服务。如果仍使用默认数据目录，保留旧的 `data` 目录，不要随程序一起删除。新程序使用相同的数据路径，启动后检查账本是否完整。当前没有安装器、自动升级或自动升级备份。

### 从格式 1 升级到格式 2

- 可直接读取旧账本及导入旧备份，不需要手工修改 JSON。读取和导出本身不会改写原文件；第一次成功保存、续费、删除或导入时写入格式 `2`。
- 旧记录按**当前到期日**建立固定日期锚点，并默认启用。例如旧文件里的 `2026-02-28` 会迁移为固定 28 日，不猜测它原来是否为 31 日或月末。请在编辑页明确修改为所需规则。
- 格式 `2` 保存续费日、月份、月末规则、启用状态，以及用于拒绝旧操作的记录版本。导入会更新记录版本，让导入前打开的编辑和续费页失效；项目 ID、名称、金额、币种、日期及规则保持不变。
- **旧程序不能读取格式 2。** 若需要回退，停止服务后使用升级前保存的格式 `1` 备份，并按上述恢复流程操作。新程序导出的备份也是格式 `2`，不能代替用于回退的旧备份；不要只改 JSON 中的版本号。

## 测试

```sh
dotnet restore RenewLedger.sln
dotnet build RenewLedger.sln --configuration Release --no-restore
dotnet test tests/RenewLedger.Tests --configuration Release --no-build --no-restore
```

测试使用 xUnit，直接引用应用项目。规则与文件存储测试之外，`WebApplicationFactory` 会检查真实 Razor Pages 请求流程，包括防伪令牌、增删改、续费确认、重复/失效操作、旧编辑页保护、停用、上传导入、下载导出、输入保留和损坏文件保护。锚点测试覆盖月末、闰年、日期上界及旧文件只读升级。

每个测试实例使用独立临时数据目录，不读取或改写自用账本。CI 在 Windows 和 Linux 上执行构建和测试；HTTP 集成测试不等同于浏览器布局、安装包或干净环境验收。
